## 1. shadcn CLI

### Base UI vs Radix
- **Base UI is the default since 2026-07-02** ("Base UI as the Default" changelog). Radix is still supported, not deprecated.
- Choose with `-b, --base <base>`: `base` | `radix` | `aria` (React Aria, added July 2026).
- `-d, --defaults` = `--template=next --preset=base-nova` (VERIFIED via `init --help` on 4.21.4; Context7 docs still say `--preset=nova`, stale).
- Running `init` without `--preset` or `--base` prompts interactively even with `-y` (shadcn skill docs).
- CI that expects Radix must now pass `-b radix`.
- The base is encoded in `components.json` `style` as a prefix: `base-<style>` / `radix-<style>` (e.g. `base-nova`).

### Commands (all VERIFIED with `--help` on 4.21.4)
```bash
# New Next.js app, Base UI, Nova style, non-interactive (VERIFIED: ran it, uses bun, writes bun.lock)
bunx shadcn@latest init --template next --base base --preset nova --name my-app --no-monorepo -y
# `create` is an alias of `init`
bunx shadcn@latest create ...
# Existing Next.js project
bunx shadcn@latest init --base base
# Add components
bunx shadcn@latest add button dialog dropdown-menu select slider tabs tooltip sonner table badge card textarea command -y
bunx shadcn@latest add toast          # Base UI native Toast (July 2026), alternative to sonner
bunx shadcn@latest add dialog --dry-run   # preview; --diff / --view also exist
bunx shadcn@latest docs button        # docs/API/examples for a component
bunx shadcn@latest info               # project info
```
Other top-level commands: `apply` (apply a preset), `view`, `search|list`, `migrate`, `eject` (inlines `shadcn/tailwind.css`, removes the `shadcn` dep), `build`, `mcp`, `preset`, `registry`. `diff` is deprecated (use `add --diff`).

Init flags: `-t/--template (next|start|vite|react-router|laravel|astro)`, `-b/--base`, `-p/--preset`, `-n/--name`, `-d/--defaults`, `-f/--force`, `-c/--cwd`, `--monorepo/--no-monorepo`, `--rtl/--no-rtl`, `--pointer/--no-pointer`, `--css-variables/--no-css-variables` (default on), `--reinstall/--no-reinstall`.

Styles seen: `nova` (default), `luma` (Mar 2026), `sera` (Apr 2026), `rhea` (May 2026). Full list and presets: ui.shadcn.com/create. UNVERIFIED whether older styles (vega, maia, lyra, mira) still ship.

## 2. Base UI

- Package: **`@base-ui/react`** (1.9.0). `@base-ui-components/react` is the old, deprecated name. Docs: https://base-ui.com
- Subpath imports per component, as shadcn does:
  ```ts
  import { Dialog as DialogPrimitive } from "@base-ui/react/dialog"
  import { Menu as MenuPrimitive } from "@base-ui/react/menu"       // dropdown-menu
  import { useRender } from "@base-ui/react/use-render"            // badge, polymorphic parts
  import { mergeProps } from "@base-ui/react/merge-props"
  ```
- shadcn wrappers type props as `DialogPrimitive.Trigger.Props` etc. and add `data-slot="..."`.

### API differences vs Radix
| Radix | Base UI |
|---|---|
| `asChild` | `render={<El />}` or `render={(props, state) => <El {...props} />}` |
| n/a | `nativeButton={false}` when `render` target is not a `<button>` (e.g. `next/link`) |
| `data-state="open"` | presence attrs: `data-open`, `data-closed`, `data-checked`, `data-unchecked`; anim attrs `data-starting-style`/`data-ending-style` |
| `event.preventDefault()` in callbacks | second arg `eventDetails.cancel()` |
| `DropdownMenu` primitive | `Menu` primitive (shadcn name still `dropdown-menu`) |
| `Dialog.Overlay` | `Dialog.Backdrop` (shadcn still exports `DialogOverlay`) |
| per-component `dir` | `DirectionProvider` |

Tailwind variants in generated components use the presence attributes: `data-open:animate-in data-closed:animate-out`.

Snippets (VERIFIED: compiled and built in a Server Component page):
```tsx
<Button nativeButton={false} render={<Link href="/" />}>Home</Button>
<DialogTrigger render={<Button variant="outline" />}>Open</DialogTrigger>
<TooltipTrigger render={<Button />}>hover</TooltipTrigger>
<Badge render={<a href="/x" />}>link</Badge>
<Slider defaultValue={[3]} min={1} max={5} step={1} />
```
Custom components passed to `render` must forward ref and spread all props onto the DOM node.

### Requested components, all exist for Base UI (VERIFIED via `add`)
dialog, dropdown-menu, select, slider, tabs, tooltip, sonner, toast (Base UI native), table, badge, card, textarea, command (cmdk; pulls in `input-group`), input, label. Primitive-free ones (card, table, textarea) are plain styled elements; badge uses `useRender`.

Sources: https://base-ui.com/react/handbook/composition, https://base-ui.com/react/overview/quick-start, shadcn skill `rules/base-vs-radix.md`, `skills/migrate-radix-to-base/*` in github.com/shadcn-ui/ui

## 3. Tailwind CSS v4 (4.3.3)

Setup (Next.js, PostCSS; VERIFIED in scaffold):
```bash
bun add -d tailwindcss @tailwindcss/postcss
```
```js
// postcss.config.mjs
const config = { plugins: { "@tailwindcss/postcss": {} } }
export default config
```
No `tailwind.config.js`, no `autoprefixer`/`postcss-import` (built in).

`app/globals.css` as generated by shadcn (abridged):
```css
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";

@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: var(--background);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  /* ...card, popover, secondary, muted, accent, destructive, border, input, ring, chart-1..5, sidebar-* */
  --radius-sm: calc(var(--radius) * 0.6);
  --radius-lg: var(--radius);
  /* ...radius-md/xl/2xl/3xl/4xl */
}

:root { --background: oklch(1 0 0); --foreground: oklch(0.145 0 0); --primary: oklch(0.205 0 0); --radius: 0.625rem; /* ... */ }
.dark  { --background: oklch(0.145 0 0); --foreground: oklch(0.985 0 0); /* ... */ }

@layer base {
  * { @apply border-border outline-ring/50; }
  body { @apply bg-background text-foreground; }
}
```
- Tokens: raw values (OKLCH) on `:root`/`.dark`, mapped to Tailwind via `@theme inline` so `bg-primary`, `text-muted-foreground`, etc. work. Convention: `X` + `X-foreground` pairs.
- Add a token: define `--warning` in `:root` and `.dark`, then `--color-warning: var(--warning);` in `@theme inline`.
- Dark mode: class-based via `@custom-variant dark`. Tailwind docs use `(&:where(.dark, .dark *))`; shadcn generates `(&:is(.dark *))`. Both fine; `next-themes` toggles the `.dark` class on `<html>`.
- `--no-css-variables` at init emits inline color utilities instead; install-time choice only.

Sources: https://tailwindcss.com/docs/installation/framework-guides/nextjs, https://tailwindcss.com/docs/dark-mode, https://tailwindcss.com/docs/upgrade-guide, https://ui.shadcn.com/docs/theming

## 4. Gotchas: shadcn Base UI + Next.js App Router

1. **Server Components can import shadcn UI directly.** Interactive wrappers carry `"use client"` (dialog, dropdown-menu, select, tabs, tooltip, sonner, command, label, table, input-group). `slider.tsx` and `button.tsx` don't, but `@base-ui/react` dist files have `'use client'` themselves, so they still work (VERIFIED: `next build` passed with all of them in a server page). You still need your own `"use client"` for event handlers/state (e.g. `toast.add(...)` callers).
2. **`next/link` in a Button/trigger** needs `render={<Link href=... />}` plus `nativeButton={false}`; omitting it triggers a Base UI warning (per Base UI docs; runtime warning not observed by me).
3. **Tooltip needs `<TooltipProvider>`** (CLI prints this after `add tooltip`). Put it in `app/layout.tsx`.
4. **Toasts**: two options. `sonner` (`<Toaster />` from `@/components/ui/sonner`, uses `next-themes`) or Base UI `toast` (`<Toaster />` from `@/components/ui/toast`, `toast.add({...})`). Pick one; both mount in `app/layout.tsx`.
5. **`suppressHydrationWarning` on `<html>`** is required by next-themes (generated layout already has it).
6. **Portals / stacking**: Base UI recommends `isolation: isolate` on an app root wrapper so portaled popups stack above content. shadcn's generated layout does NOT add it; add `<div className="isolate">` around children if z-index issues appear.
7. **Don't copy Radix snippets.** `asChild`, `data-[state=open]:`, `onOpenChange(open)` without `eventDetails`, and `DropdownMenu` primitive names are Radix-only. Most blog/LLM examples still use Radix.
8. **`cn` import**: new components import `cn` from the `cn` npm package, not `clsx`/`tailwind-merge`. Keep `lib/utils.ts` re-export for your own code.
9. **React version**: Next 16.4 ships React 19.3; Base UI supports React 17-19. No extra flags needed (no `--legacy-peer-deps` with bun).
10. **Next 16 AGENTS.md**: `next dev` (re)writes an agent-rules block into `AGENTS.md` telling agents to read `node_modules/next/dist/docs/`. Commit it or it keeps reappearing.
11. Non-interactive `init` must pass `--base` or `--preset`, otherwise it prompts.
